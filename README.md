## 安装

把仓库放入 `ComfyUI/custom_nodes/ComfyUI-MiniMaxH3-Myang`，然后重启
ComfyUI。GitHub 仓库创建完成后可使用：

```powershell
cd ComfyUI\custom_nodes
git clone https://github.com/civilcoco/ComfyUI-MiniMaxH3-Myang.git
```

运行时必需：

- 支持官方 MiniMax H3 节点的较新版本 ComfyUI；当前验证基线为
  `43cb4fffc89bba20ab7bd61467a36d0339338dab`。
- MiniMax H3 diffusion model、Qwen text encoder、video VAE 和 audio VAE；
  请从模型发布方获取，本仓库不提供下载副本。

核心节点不要求安装其他第三方节点包；Media Agent 已内置。完整示例工作流另外使用
VideoHelperSuite、SolAttn、Spectrum、EasyCache、
SageAttention、KJNodes/PreviewAny 等可选节点；缺少时可安装相应包，或旁路/删除这些
外围优化节点，Myang 核心长视频节点仍可独立使用。

Media Agent 的素材整理、直通模式、严格引用校验和 LLM/VLM 调用都已在本包内实现，
不再要求安装 Prompt Assistant。ComfyUI 设置页左侧进入 `Myang_node`，打开
“LLM 服务设置”即可配置 OpenAI-compatible 或 Ollama 服务。内部 ID 是旧工作流稳定
标识，节点下拉只显示“显示名称 :: 模型名”；已有服务的 ID 不允许原地修改，避免历史
工作流静默失效。API Key 不会由读取接口返回到浏览器；编辑框留空即保留原值。
一个服务可以配置多组独立 URL/Key，并选择轮询或主线路优先。429/TPM、超时、连接、
鉴权和服务端故障只会冷却当前线路，其他健康线路会立即接手；冷却按 API Key 组共享，
不会被同一服务的另一个模型或 Agent 阶段绕过。LLM 设置与 Agent 技能管理面板都会显示
不含密钥的实时线路状态，并提供手动重置冷却/熔断的入口。

若检测到旧 `prompt-assistant/config/config.json`，面板会只读导入并去除完全重复的
服务；第一次保存才写入 Myang 自己的
`user/default/Myang_node/config/llm_services.json`，不会改动旧插件配置。旧工作流里的
`服务ID/模型` 和 `显示名称/模型` 两种写法继续兼容。音频转写仅在选择 Whisper 模型时
需要可选的 `openai-whisper`。

## Myang 导演台

“沐阳 H3 · 导演台（全功能）”是现有节点之上的控制层，不是另一套采样核心：

- 手动分镜卡：每个镜头独立开关、标题、提示词和时长，时长自动吸附到 H3 的
  `17k+5` 帧网格；不同镜头可以使用不同长度。镜头卡内可直接上传、预览并引用
  最多 9 张图片、3 个视频和 3 个音频，视频可标记为该镜头的动作源。
- 逐镜头素材：默认使用“仅本镜头”并从 `@图片1 / @视频1 / @音频1` 编号；也可
  选择“叠加全局素材”，在 Media Agent 素材之后追加。工作流仅保存 `ComfyUI/input`
  文件引用，运行到对应镜头时才解码，避免把大媒体写进工作流 JSON。
- 智能切分：可直接接 Media Agent 的 `myang_prompt`，一次调用 LLM 拆成整条时间线；
  关闭 LLM 时原提示词直通，不消耗 Token。
- 原有能力全部复用：Media Agent 多素材、模型加载、Turbo/Sigma Shift、原生多关键帧
  锚点、40Hz 音频接缝、逐段保存和导演台内置二采。
- 『一采模型』同时接受普通模型和 Turbo 联合模型。接 Turbo 时，导演台显示档位推荐步数，
  实际步数仍在同一个『一采步数』控件里调整，并自动使用 `simple` 和 `denoise=1.0`。
- 二采默认关闭；导演台内的折叠面板可直接设置模式、输出分辨率、神经 3D/Latent/
  像素/RTX VSR 放大、采样参数、轮数和种子策略。开启后才显示“同时保存二采前分段”。
- 原 `H3ScriptSplitter`、`H3LongVideo` 与独立二采节点均保留，旧工作流继续兼容，复杂
  工作流仍可拆开接线；导演台自身只保留内置二采面板和确有独立用途的数据入口。

导演台仍把同一次任务的“动作迁移 / 视频续写 / 纯生成”作为全局模式，但动作迁移可由
每张分镜卡提供自己的“动作源”视频；未设置时才回退到节点的全局 `ref_video`。
镜头素材不会替代 Media Agent：前者适合镜头独占素材，后者适合全片共享素材和 LLM/VLM
整理，两者可在“叠加全局素材”模式中共存。

### 公共素材（全片共用）

导演台顶部有一块「公共素材」，可以直接上传全片共用的角色图、场景图、参考视频和配乐，
不必再单独接一个 Media Agent 节点。给每个素材填一个主体名（例如“女主角正面照”），
它会写进素材清单里。

- **Agent / 长剧本智能切分**：素材清单连同剧本一起交给 LLM，由它逐段判断这一段画面里
  出现了哪些素材、该写哪些 `@图片N` 标签——角色图会被带到每一段有这个角色的分段，
  用不到的素材不会硬塞。关掉智能切片时，各段共用全部公共素材。
- **手动分镜卡**：镜头卡选「叠加全局素材」就能拿到公共素材，编号排在镜头专属素材之前；
  选「仅本镜头」的镜头拿不到，和原来对 Media Agent 的语义一致。
- 已接 Media Agent 时两者叠加：Agent 的素材在前，导演台上传的排在后面编号。
- 动作迁移和视频续写只允许左侧 `ref_video` 一条视频，所以公共素材里放视频会直接报错，
  图片和音频不受影响。

素材编号（`@图片1` 里的 1）按类型分别计数，和 `H3Condition` 实际接收的顺序一致，
清单里给 LLM 的标签就是生成时能解析的标签。

### 写作技能与素材识图（智能切分）

发布包不内置 MiniMax Hub 或 MiniMax H3 官方技能正文。节点在没有外部 Skill
时会使用代码内置规则；用户也可以自行安装具有适当使用和再分发许可的 Skill。

“Agent / 长剧本智能切分”现在和 Media Agent 用同一套技能与素材处理，不再是两套写法：

- **写作技能**：`skill_preset` 从 `skills/` 目录或
  `MINIMAX_H3_SKILLS_DIR` 指向的个人目录中选择技能包，它规定每段提示词的输出
  结构、分镜格式、时长规则、素材标签写法和禁止事项。`auto` 会在拆分前用一次很短的调用，
  只看技能的名称/分类/摘要来挑一个，不会把整包技能塞进去。`none` 使用默认 H3 提示词写法。
- **技能记忆**：优先使用本机 `_skill_memory.json` 里 LLM 学习后的精简规范（几千字），而不是
  原始技能包（几万字）；没学过的技能按预算截断读取，优先保留写作章节。技能文件改动后
  索引和记忆会一起失效重建。
- **自定义写作规则**：`skill_text` 里写的规则排在所选技能之前，优先级最高。
- **分段数量不受技能影响**：技能文档里的示例镜头数和示例秒数一律不作数，段数和每段时长
  仍由导演台的总时长/单段时长决定。
- **素材识图 VLM**：`vlm_service` 打开后，拆分前先让 VLM 逐个看公共素材，把画面内容写进
  素材清单；音频接了 Whisper 时还会带上真实语音。LLM 于是能按“这段画面里有谁”来分配
  `@图片N`，而不是靠文件名猜。关闭时清单只给主体名、文件名、分辨率和时长。

技能内容和素材清单都进拆分缓存键：换技能、改自定义规则或换素材都会重新拆分，不会复用出
按旧规范、旧编号写的段提示词。

### 段间衔接由 LLM 逐段判断

拆分规则不再要求所有段落都平滑延续。LLM 会按剧本自己决定每个分界点是：

- **承接**：同一场景内动作连续，上一段结尾的镜头位置、人物姿态和环境延续到本段开头；
- **切镜**：剧本在这里换了场景/时间/视角/主体，本段直接进新镜头，并把机位、景别、环境和
  人物状态完整重写一遍，不依赖上一段的描述。

每段的判断结果写在 `transition` 字段里，面板上显示成标签（切镜是黄色）。第 1 段固定「开场」。

一点实现上的实话：段间锚点是**始终存在**的，系统总会用上一段结尾做约 0.92 秒（22 帧
@24fps）的接缝锚点，成片里会裁掉。所以「切镜」是靠这一段正文的画面内容切过去，不是真正
的硬切黑场；提示词里也明确禁止 LLM 写黑场/闪白/转场特效指令，那些 H3 做不到。

### 拆分失败不再拿整段剧本凑数

以前 LLM 返回空或非 JSON 时，代码会拿**整段剧本**复制 N 份当作 N 段——看上去跑成功了，
实际每段生成的都是同一个画面。现在：

- **重试阶梯**（和 Media Agent 同一套思路）：每级换种子重试 2 次（推理模型重放同一种子会
  复现同样的空回复），下一级再缩短请求——先去掉技能，再去掉素材规则，最后只剩骨架，
  token 上限同步下调 `None → 3000 → 1500`。
- **一段都没拿到就直接报错**并说明原因和三条处理办法，不伪造分段。只拿到几段（少于目标
  段数）才用末段补齐，那至少是剧本结尾的真实内容。
- **时长算式说清楚**：`5 段 × 8.00 秒 = 40 秒` 和「成片 36.3 秒」看起来矛盾，是因为相邻段
  有 0.92 秒重叠会被裁掉。以前只给结果不给理由，推理模型会把整个额度花在验算这个矛盾上，
  正文返回空。现在这三个数字一起给，并明确说不需要验算。

### 看每段实际拆出来的提示词


智能切分的分段提示词是运行时才由 LLM 写出来的，所以导演台面板里多了一块「本次拆出的
分段提示词」：运行后会列出每一段的标题、时长帧数和完整提示词，`@图片1` 这类素材标签
渲染成带缩略图的标签，`<d>台词</d>` 单独高亮，可以直接核对 LLM 有没有把素材分对。
正在生成的那一段会高亮，每段右上角可以一键复制原文。

手动分镜卡模式不显示这块——那里的提示词本来就是你自己在镜头卡里写的。

### 动作迁移断点续跑

一条动作参考视频被切成 N 段后，如果只跑出了前几段就中断，不必整条重来。在动作迁移
面板的“断点续跑”里把“起始段”改成没跑完的那一段，再把上一段的成片接到左侧的
`前段视频` 输入即可：

- 参考视频、参考图片和提示词照旧连接，分段网格不变——第 X 段仍然从它在完整分段里
  原本的那一帧开始取动作片，画面不会错位。
- `前段视频` 只用来取结尾的锚点帧做段间接缝，走的是 Motion Context 通道，不会作为
  `@视频1` 参考素材参与 ref2va 调用。可选再接 `前段音频` 做声音接缝。
- 落盘文件名保留绝对段号（例如 `_第06段`），可以直接和先前跑出的分段拼在一起。
- 起始段为 1 时必须断开 `前段视频`，起始段大于 1 时必须接上，避免两种状态混淆。
- 这两个控件只属于动作迁移。切到别的任务模式后它们会被忽略并自动归位，不会拦住执行。

## 二采与神经 Latent 放大

“沐阳 H3 · 二采放大设置”现在提供三种互斥模式：放大后二采、同分辨率二采、仅放大
不二采。放大方式包括像素/VAE 投影、RTX VSR、原来的 bislerp Latent 插值，以及新的
`neural_3d` 学习型 24 通道 H3 Latent 放大。

神经模式兼容 LBH-123-AI 发布的 Apache-2.0 3D 权重。权重不会随本仓库分发，请自行放到
`ComfyUI/models/latent_upscale_models/`。推荐先用 fp16、时间分块 16；显存紧张改 8，出现
色块或精度异常时改 fp32。放大器完成后立即卸回 CPU，再启动 H3 二采。它主要节省
MiniMax H3 大型 VAE 的 decode → resize → encode 时间；目标分辨率二采本身的峰值显存
不会消失。

可直接打开示例工作流：
`example_workflows/Minimax_H3_Myang_Director_CN.json`。安装目录内另复制到
`ComfyUI/user/default/workflows/minimax/`，重启或刷新工作流列表后即可选择。

权重与说明：<https://huggingface.co/LBH-123-AI/Minimax_h3_latent_Upscaler>

## 这版解决了什么

- 任意位置、多关键帧：不再局限于官方的首帧/尾帧锚点。
- 段间视频续接：把上一段尾部 temporal latent 钉到新段开头。
- 参考素材共存：修复 keyframe latent 被 image/video refs 覆盖的问题，顺序严格为
  `keyframes → reference videos`。
- 声音续接：视频仍按 24fps，声音独立按 40Hz。锚点只占用切点前完整的
  40Hz step（向下取整），不足 25ms 的分数步留作安全区，再在真实波形切点
  用 20ms 同内容交叉淡化；不会把上一小段音乐四舍五入到下一段重复。
- Sol-Attn：识别其只读 PackedLayout observer，按
  `Sol observer(Myang anchor(stock))` 的顺序安全组合。
- 原工作流兼容：已有 `H3LongVideo` widget 保持原顺序，新接缝选项只追加在末尾，
  不需要重建工作流。
- 高动态细节：可选在 H3 原生采样轨迹的低 Sigma 尾段增加积分点，减少低步数时
  最后几步跨度过大带来的细碎噪点；默认关闭，便于同 seed 做严格 A/B。
- 二采放大：低分辨率一采后逐段在 CPU 分块放大，再用未挂 Turbo LoRA 的
  Ref2VA 基模做低降噪二采；最终音频完全旁路二采，避免音乐尾部被重新生成。

## 段间算法

`H3LongVideo.context_length` 与 `H3ScriptSplitter.overlap_frames` 必须相同。

| 值 | temporal blocks | 定位 | 说明 |
|---:|---:|---|---|
| 22 | 7 | 默认、稳定 | 连续上下文较多，建议先用它验证成片 |
| 5 | 2 | 实验速度锚点 | 保留两个时序 VAE block，分别携带位置与短时运动趋势 |
| 39 | 12 | 加强连续 | 更强约束，token 与裁帧更多 |
| 56 | 17 | 最长连续 | 只在确有需要时使用 |

典型 8 秒目标有 57 个 temporal blocks：22 帧模式增加约 `7/57=12.3%`
的视频条件 token；5 帧模式约 `2/57=3.5%`。5 帧还只裁掉输出的约 2.6%，
但它是否能在你的素材上达到 22 帧的稳定性必须实际 A/B，因此仍标为实验，不设默认。

相比“取最后三张图分别编码”，5 帧方案更适合 H3：它正好跨两个 temporal
blocks，可以直接从上一段 sampler latent 无损切出，不需要解码再逐帧重编码。

锚点调度以窗口末端为真正接缝：`渐疏`在最后三个 temporal block 最密，向前
隔步放开；`仅贴缝`只保留最后两个 block。画面淡化也只使用钉入窗的最后 N 帧，
而不是把整段 22 帧都重写。

## 低 Sigma 高动态精修（实验）

对南风 H3 V4 公共包的图结构核验表明，它用于“高动态噪点”的主要有效候选并非
图像后处理，而是官方 ComfyUI `ExtendIntermediateSigmas`：在接近成片的低噪声
区间加密数值积分。Myang 没有复制或依赖该包代码，而是直接组合 ComfyUI 官方节点。

- `关闭（H3原生轨迹）`：完全保持原采样轨迹，也是默认值。
- `低Sigma精修（均衡·实验）`：仅在 `sigma <= 0.8` 的区间用 cosine 插入 1 个点；
  典型 8 步任务约从 8 次增加到 10 次模型评估（约 +25%）。
- `低Sigma精修（强化·更慢）`：同一区间插入 2 个点，典型约 12 次（约 +50%）。

这里刻意保留 H3 训练时的视频/音频 shift `12/3`，也不把采样拆成两次。后者会在
分界处重置 `res_multistep` 一类多步求解器的历史，不能视作连续积分的等价优化。
低 Sigma 精修本身不会改 shift；只有下面单独的 Turbo 调度节点会按对应 LoRA 的
官方训练档位显式设置它。建议先用相同素材、seed、8 步比较“关闭”和“均衡”。

## LightX2V Turbo LoRA 调度

参数依据：[LightX2V 模型发布页](https://huggingface.co/lightx2v/Minimax-h3-Turbo) 与
[发布方 ComfyUI 工作流](https://github.com/ModelTC/Minimax-H3-Turbo/tree/main/example_workflows)。

`沐阳 H3 · Turbo LoRA 联合音画加载调度` 已融合标准 `LoraLoaderModelOnly`：新工作流
直接选择 LoRA 文件和模型强度，节点先调用 ComfyUI 官方仅模型加载器，再调用官方
`MiniMaxH3SigmaShift`，同步视频 sigma、DiT 内部反推的公共时间网格和音频 sigma。
旧工作流仍可保留上游 LoRA 节点，并把『LoRA文件』设为『不在本节点加载』；这是默认值，
所以升级不会静默重复挂载 LoRA。

| LightX2V 档位 | video/audio shift | 官方推理 NFE | 训练分辨率 |
|---|---:|---:|---|
| v1.0 8-step | 12 / 3 | 8 或 4（建议先 8） | 544p 混合比例 |
| v1.0 4-step 768P | 6 / 3 | 4 | 1344×768 |
| v0.1 4-step | 12 / 3 | 4 | 544p 混合比例 |
| Ref2VA v0.1 4-step | 12 / 3 | 4 | 544p 混合比例 |

『自动匹配 LoRA 文件』会识别官方 ComfyUI 文件名中的 `ref2va`、`4step`、`8step` 和
`768p`。显式档位与可识别的文件名冲突时会提前报错，避免把 6/3 与 12/3 交叉使用。

当前循环工作流使用 `minimax_h3_fl2v_turbo_8step_v1.0_comfyui_bf16`，所以适配节点
设为 `12/3`、长视频 `8步 + simple`、采样器 `Euler`。LoRA 强度仍保留工作流原值
`0.75`；LightX2V 示例使用 `1.0`，可自行 A/B，不在迁移时擅自覆盖。

Turbo 是固定 NFE 蒸馏轨迹，因此长视频节点会拒绝错误步数、非 `simple` scheduler、
非 `1.0` denoise 和非 Euler 采样器。若旧工作流误把“低 Sigma 精修”留在开启状态，
节点会自动忽略它并保持官方固定 NFE 网格，而不是等模型加载后才报错。低 Sigma 插点
会改变训练时的 NFE 网格，不能把两种加速/精修方案直接叠加。

LightX2V 现在同时发布 FL2VA/T2VA 与 Ref2VA Turbo。纯生成/首尾帧优先选择 FL2VA，
动作迁移优先选择 Ref2VA；若把 FL2VA 档接到动作迁移或续写，节点会给出任务族警告。
Myang 的多段原生锚点续写仍属于本包自己的长视频扩展，并非发布方示例图，仍应重点
检查接缝动作、口型和音频。

## 二采放大精修

参考工作流的有效链路是“一采低分辨率 → 像素放大 → VAE 重编码 → 低降噪二采”。
Myang 按长视频重新组织了它：每段单独二采，不把整部成片一次送进二采显存；放大结果
固定回收到 CPU float16，并按独立节点的 `chunk_frames` 分组（最终合并仍需要容纳成片的
CPU 内存）。`nvidia_rtx_vsr` 使用本机 NVIDIA VFX 的 ULTRA 档，每次只把一帧送入
GPU，输出立即回收到 CPU，不沿用参考节点的整批 CUDA 暂存。针对 Windows 上
`nvvfx 0.1.0.1` 可能在释放实例时卡死的问题，RTX VSR 会在隔离进程内执行，
通过磁盘映射交换 CPU float16 帧；会多用临时磁盘，但不会因 VFX 释放故障卡住
ComfyUI 主进程。H3 video VAE 继续使用
ComfyUI 官方实现自带的 256px 空间块与 17 帧时间块，无需额外清缓存节点。

二采必须连接同一补丁链中、`LoraLoaderModelOnly` 之前的 Ref2VA 模型。当前循环
工作流已经把这条线接好；它共享原模型权重，不会再加载第二份 H3。Turbo 输出会被
明确拒绝，因为 `beta + denoise 0.2` 的二采轨迹不是 Turbo 固定 NFE 轨迹。

循环工作流里有独立的 `沐阳 H3 · 二采放大设置` 节点。`enabled` 是总开关，默认
关闭；Turbo LoRA 之前的 Ref2VA 基模接入该节点的中文输入『二采模型』，然后只用一条
『二采设置』连线接到长视频节点。长视频节点不再显示重复的二采参数。

推荐先从以下组合做两段 A/B：

- 一采 720P 时，二采先选 832P；显存有余量再试 928P。
- `4 steps / denoise 0.2 / beta / res_multistep`；先用 `bicubic` 验证，RTX 显卡可再选
  `nvidia_rtx_vsr` 比较细节。
- `chunk_frames=4`；这是 CPU 放大批量，不改变 H3 的时间连续性。
- 最终音频仍走一采原波形，只在既有 `H3SeamBlend/H3AnchorTrim` 中做接缝与精确时长。

独立的 `沐阳 H3 · 二采放大精修` 节点可用于单段图；音频输入只用于 H3 联合音画
二采的 latent，节点不输出改写后的音频，原音频应沿原连线直接送到成片节点。

## 节点

- `沐阳 H3 加载器`：配置 Ref2VA 与 FL2VA 两个 diffusion model、CLIP、video
  VAE 和 audio VAE；扩散模型按任务惰性加载，不会同时驻留。
- `沐阳 H3 条件（提示词 + 素材）`：调用官方
  `MiniMaxH3ReferenceToVideo`；支持 Agent 素材包，也支持循环内部的直接
  `ref_video`。
- `沐阳 H3 · 分段计划`：按 H3 官方 `17k+5` 网格规划分段，固定 24fps。
- `沐阳 H3 · 长视频（原生多关键帧）`：运行时展开 N 段采样链。
- `沐阳 H3 · Turbo LoRA 联合音画加载调度`：加载或沿用 LoRA，并设置成对的 video/audio shift，
  并向长视频节点留下可验证的步数契约。
- `沐阳 H3 · 二采放大精修`：CPU 分块放大、原生 H3 低降噪重绘；保留原音频。
- `沐阳 H3 · 二采放大设置`：长视频二采的独立开关和参数面板。
- `沐阳 H3 · 段间多关键帧`：通常由长视频节点内部使用。
- `沐阳 H3 · 任意位置关键帧`：把指定姿势钉到本段任意帧；可串联多个，也可与段首续接组合。
- `沐阳 H3 · 锚点同步裁剪`：同步裁画面与声音。
- `H3 接缝淡化`：用钉入窗末端的对应画面和切点前 20ms 对应波形消除硬切，
  并把每段音频严格截到交付帧数的时长。

## 快速使用

1. 打开
   `example_workflows/Minimax_H3_Myang_LongVideo_CN.json`。发布包中的示例已清除
   私人素材文件名；请重新选择自己的图片、动作参考视频和可选音频。
2. 动作迁移使用 Ref2VA 权重。当前循环工作流已迁移到
   `minimax/minimax_h3_ref2va_int8_convrot.safetensors`。
3. 先保持 `overlap_frames=22`、`context_length=22`，用两段短片验证接缝。
4. 想启用二采时，在独立的“二采放大设置”节点打开 `enabled`；建议先选 832P。
   工作流已把 LoRA 前的模型支路接到 `refine_model`。
5. 高动态镜头有细碎噪点时，保持其余参数不变，把 `低 Sigma 精修` 改为“均衡”做 A/B。
6. 再把两处同时改为 `5`，做相同 seed/提示词/素材的 A/B。
7. 多段后出现偏暗或偏饱和累积时，再开启漂移校正；建议从
   `mean_std`、强度 `0.6` 开始。

动作迁移会在采样前检查参考视频是否足够长，不再等尾段只剩 1～4 帧时才失败。
漂移校正走像素回传；若短段配 56 帧大窗口导致裁后不足下一窗，也会在采样前明确报错。

## 素材与提示词

不连接 Agent 时，动作迁移的分段切片会直接作为 `ref_video_1` 送入官方
Ref2VA，提示词中的 `@视频1` 会转换为 `<Video 1>`。

连接本包内置的“沐阳 H3 · Media Agent”是可选用法：Agent 负责素材预览、编号、
LLM 改写和 `@图片N/@视频N` 校验；长视频展开内部仍只使用官方 H3 与 Myang 节点。
编辑器提示词输出名为 `myang_prompt`，并直接使用 `@图片N/@视频N/@音频N`；采样用的
`agent_prompt` 则直接输出官方 `<Picture N>/<Video N>/<Audio N>` 标签，不经过私有占位符。现代 `VIDEO`
对象会被拆成 24fps IMAGE 帧批，内嵌声轨按相同视频序号送入官方
`ref_video_audio_N`。

## 兼容与故障提示

- `ComfyUI-H3-Motion-Context` 可以留在 `custom_nodes`，它的补丁是惰性安装；但不要在同一个 ComfyUI 进程里先运行旧 Motion-Context 再运行本包锚点。
- 如果已经运行过旧节点，请重启 ComfyUI，再只运行 Myang 工作流。
- 本包运行时不依赖 Motion-Context 节点，但原生锚点包含从其 GPL-3.0 实现改编并
  继续发展的代码；版权、版本和修改范围已在 `THIRD_PARTY_NOTICES.md` 明示。
- Sol-Attn 无论先于或后于 Myang 安装，都有 CPU 回归覆盖。
- 未裁剪 H3 模型触发 `hostbuf_grow ... beyond reserved` 时，本包会让 Windows
  aimdo 的大模型 HostBuffer 虚拟地址范围至少覆盖实际模型大小；这只改变地址
  上限，ComfyUI 的 40% pinned RAM 上限保持不变，也不会自动替换成 pruned 权重。
